# Demo recording plan

Status: recording not supplied. This is a recording plan, not evidence that the
host acceptance tests have passed. Show the real supported host and production
connector. Use the dedicated reviewer account and synthetic fixtures. Never
record passwords, cookies, signed upload/download URLs or unrelated account data.

## Sequence

1. Show the installed candidate version and successful account connection (P1).
2. Attach demo-bracket.step, request the direct drawing, show the resulting preview
   and specific validation evidence, then open the actual PDF attachment or clearly
   show the supported private-link fallback (P2). Do not label unchecked decisions
   as approved.
3. Open blind-hole-block.step in Specify (P3). Rotate the part and click a flat
   face. Ask chat to read the explicit selection. Show unconfirmed choices and
   confirm that the small bore is not silently assigned an M2 thread.
4. Set steel, plus/minus location and a plain unthreaded blind hole. Read the
   remaining proposals aloud/on screen before explicitly accepting them (P4).
   Export STEP with confirmed PMI without generating a drawing. Show the returned
   actual STEP file, writer warnings and preserved working session. Confirm that
   the file can be re-imported in Specify; do not infer correctness from its name.
5. Generate from those same saved decisions (P5). Show the preview, detailed
   findings/unknown checks, exact PDF and generation STEP output. Keep a plain bore
   plain, and do not claim complete standards certification.
6. In a separate chat ask the unrelated weather prompt and show no Draftwright
   invocation (N1).
7. Open a fresh bare blind-hole part, ask for PMI export before confirming any
   proposals, and show the clarification/refusal rather than an invented export
   (N2).
8. Ask for the synthetic unowned artifact and show the safe authorization failure
   with no file or private link (N3).

Record the runs in order; wait visibly or trim idle waiting with an honest label.
Capture every case's outcome and the actual calls in results.json. If the visual
card or native file delivery is not available on a particular host, record that
fallback rather than presenting another host's behavior as universal.

Record all eight cases on each supported distribution surface before submission.
Upload the recording to a reviewer-accessible HTTPS location; verify access from
an isolated browser. Enter that URL in Review details or in the supported
review.demo_recording_url field, then rebuild the candidate package if needed.
